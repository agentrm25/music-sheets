# PDF Output Style Handoff

Status: current behavior as of 2026-08-21. This document describes the PDF generated by `ChartApp.exportPDF()` in [`src-js/import-export.js`](src-js/import-export.js). When older prose or the live preview disagrees with the exporter, the exporter is authoritative.

## 1. Design intent

The PDF is a compact, stage-readable song chart rather than conventional sheet music. Its visual language is:

- a plain white US Letter page;
- one centered reading column;
- large Helvetica text that can be scanned from a music stand;
- strong color cues for chords, section types, instructions, and verse numbers;
- minimal decoration, limited to brackets around arrangement notes and a small page count;
- no editor chrome, theme styling, card backgrounds, staff notation, tables, or private workflow data.

## 2. Page geometry

| Property | Current PDF behavior |
| --- | --- |
| Page | US Letter, portrait, 612 x 792 pt |
| Left and right margins | 40 pt |
| Printable content width | 532 pt |
| Top margin | 24 pt |
| Footer reservation | 20 pt in the exporter's page budget |
| Content break boundary | `y = 748 pt` |
| Alignment | All visible chart content is horizontally centered |
| Background | Unstyled white page |

The footer is added after all chart content has been laid out. It is 9 pt gray Helvetica and reads `current / total`, for example `1 / 3`. Its right edge sits 36 pt from the page edge. There is no running title, date, band name, or other repeated header.

## 3. Content order and hierarchy

When fields are present, the exact order is: quoted song title, artist, BPM and time signature, current/original key, capo, bracketed arrangement notes, sections and their lines, then the page count on every page.

Empty metadata fields are omitted without leaving a placeholder. The chart begins at the top margin, and later elements move upward naturally when earlier fields are absent.

### Metadata treatment

- The title is wrapped in curly double quotation marks, such as `“Song Title”`.
- BPM is formatted as `126 BPM`.
- If BPM and meter both exist, a centered bullet separates them: `126 BPM • 4/4`.
- The key line is `Key: D`.
- If an original key exists, it stays on the same PDF line: `Key: D (originally in E)`.
- Capo is formatted with a spaced hyphen: `Capo - 2`.
- All metadata is black and centered.

## 4. Typography

PDF text uses jsPDF's built-in Helvetica family. There is no custom font file. The live preview may select Helvetica Neue first, but the exported file explicitly selects Helvetica.

| Element | Size | Weight/style | Color |
| --- | ---: | --- | --- |
| Title | 17.6 pt | Bold | `#000000` |
| Artist | 14 pt | Regular | `#000000` |
| BPM and meter | 12 pt | Italic | `#000000` |
| Key and capo | 17.6 pt | Regular | `#000000` |
| Arrangement notes | 15.5 pt | Italic | `#444444` |
| Section label | 17.5 pt | Bold, uppercase | Section color |
| Chord line | 16 pt | Bold | `#1a55d4` |
| Lyric line | 17.6 pt | Regular or bold | `#000000` |
| Instruction line | 15.5 pt | Italic | `#cc00cc` |
| Page count | 9 pt | Regular | `#787878` |

Normal line advancement is `font size x 1.35`. Effective line height therefore changes when a long line is scaled down.

## 6. Arrangement notes

Arrangement notes are the only multi-line text that intentionally wraps.

- Notes sit between the metadata stack and the first section.
- The text is centered, italic, and dark gray.
- A square-bracket motif frames the block: gray vertical rules on both sides with 9 pt horizontal caps at the top and bottom.
- The bracket strokes are `#666666` at 1.25 pt.
- The brackets begin 68 pt from the left page edge and end 68 pt from the right page edge.
- Text wraps within an approximately 430 pt inner width.
- The block adds 16 pt beyond the wrapped text height.

## 7. Sections and line types

Every section begins after a 17.6 pt vertical spacer unless it has been moved to a fresh page. Non-verse sections then display a centered, bold, all-caps label. Verse sections intentionally have no `VERSE` heading.

For non-verse repeats, the heading receives a multiplication suffix such as `CHORUS × 2`. Verse repeat values are not printed.

### Verse treatment

The first rendered lyric in a verse receives a colored prefix such as `[2] ` and the entire line is bold. Chord rows before that lyric do not consume the first-lyric slot. Later lyrics use their own regular/bold setting.

### Chords

Chord rows are centered, blue, and bold. Spacing typed into the chord string is preserved by jsPDF's text placement only to the extent supported by Helvetica; there is no bar grid, chord cell, or fixed-width font.

### Lyrics and inline emphasis

Lyrics are centered and black. A line can be regular or bold. Text wrapped in `**double asterisks**` is emitted without the markers and toggles weight relative to the line's base weight:

- on a regular lyric, marked text becomes bold;
- on a bold lyric or the first lyric of a verse, marked text becomes regular.

This toggle behavior is intentional in the current implementation, even though it differs from ordinary Markdown's always-bold semantics.

### Instructions

Instructions are centered, italic, and magenta. Parentheses are not added automatically; if the output should show `(Half-time)`, the parentheses must be present in the stored text.

### Grid lines

A grid line is rendered as two stacked rows: blue bold chords first, then the associated black lyric. It has no visible container, rule, or background. The two rows are paginated independently, so a page break can separate a grid's chord row from its lyric row.

## 8. Fitting and pagination

Titles, metadata lines, section labels, chords, lyrics, and instructions are single-line elements. If one is wider than the 532 pt content area, its font size is reduced proportionally. Scaling stops at 60% of the base size.

Important consequence: these elements never wrap. A line that is still too wide at 60% can extend past the page edges and be clipped. Arrangement notes are the only wrapping content type.

Before a section starts, the exporter budgets space for its leading spacer, heading, and first rendered line. If that group will not fit, the entire group starts at the top margin of a new page and the leading spacer is omitted. This avoids an orphaned heading.

After the first line, each row is checked independently. A section can continue on the next page, and its heading is not repeated. A grid's chord and lyric rows can split. Extremely long arrangement-note blocks are kept as one block rather than split across pages, so they can overflow a page.

## 9. Live preview versus exported PDF

The preview in [`src-js/preview.js`](src-js/preview.js) and [`style.css`](style.css) is a close visual guide, not a pixel-identical PDF renderer.

| Area | Live preview | Exported PDF |
| --- | --- | --- |
| Canvas | 612 x 792 CSS px with rounded corners and shadow | 612 x 792 pt plain page |
| Typeface | Helvetica Neue, then Helvetica/Arial fallbacks | Helvetica |
| General line height | 1.4 plus CSS margins | 1.35 with exporter-controlled advancement |
| Original key | Separate line when present | Appended to the current-key line |
| Instructions | Bright `#ff12ff`, upright | `#cc00cc`, italic |
| Page breaks | Dashed visual estimates | jsPDF measurement and explicit page budgeting |
| Paper chrome | Radius and shadow | Neither exports |
| App theme | Affects surrounding UI | Never affects PDF |

There is also a current verse-color mismatch above verse 5: the PDF correctly uses gray for verse 6+, while the preview's CSS class is clamped to the verse-5 green class. Treat the PDF palette as the output contract.

## 10. Included, excluded, and file naming

The PDF includes only public chart content: title, artist, tempo, meter, keys, capo, arrangement notes, sections, chords, lyrics, instructions, repeat cues, and page counts.

It excludes chart ID, group, status, source, private info notes, saved versions, collected-section metadata, favorites, editor collapse state, editor heights, and all application UI.

The filename is derived from the title by retaining only ASCII letters, digits, and spaces, then trimming outer spaces. Punctuation, symbols, and non-ASCII letters are removed. If no usable title remains, the file is named `chart.pdf`.

## 11. Implementation ownership

- [`src-js/import-export.js`](src-js/import-export.js): authoritative PDF layout, typography, line fitting, page breaks, footer, and filename behavior.
- [`src-js/constants.js`](src-js/constants.js): section and verse colors.
- [`src-js/preview.js`](src-js/preview.js): shared inline-bold parsing and verse-prefix logic, plus preview rendering.
- [`style.css`](style.css): preview-only paper styling and duplicated chart design tokens.
- [`tests/pdf-font-consistency.test.js`](tests/pdf-font-consistency.test.js): regression coverage that grid chords and lyrics use Helvetica with the expected base weights.

## 12. Verification checklist

For any PDF-style change:

1. Run `node --test tests/pdf-font-consistency.test.js`.
2. Export a representative chart containing all metadata fields, arrangement notes, every section type, repeats, verses 1 through 6, all four line variants, regular/bold lyrics, and inline emphasis.
3. Include enough content to force at least two pages and place a grid near a page boundary.
4. Render every PDF page to images and inspect title hierarchy, bracket alignment, colors, line weights, page splits, clipping, and footer placement.
5. Confirm the PDF is US Letter portrait at 612 x 792 pt.
6. Confirm private Info fields do not appear.
7. Compare the live preview, but resolve discrepancies in favor of the explicit exporter contract or make an intentional coordinated change.

## 13. Current constraints to preserve or address deliberately

- The PDF is visual and print-oriented; it is not tagged for accessibility and has no bookmarks or semantic structure.
- Long single lines can overflow after reaching the 60% scaling floor.
- Long arrangement-note blocks do not split across pages.
- Grid chord and lyric rows can split across a page boundary.
- Section headings are not repeated when a section continues on another page.
- Helvetica metrics differ slightly from the preview's preferred Helvetica Neue metrics.
- Existing older documentation may call the footer `Page X of Y`; the actual output is `X / Y`.

These are current-output facts, not necessarily permanent product requirements. Any change to them should be treated as a visible PDF contract change and verified with rendered multi-page output.
